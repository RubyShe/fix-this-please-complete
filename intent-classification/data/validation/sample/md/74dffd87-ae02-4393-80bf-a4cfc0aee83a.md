The fix is pushed. Here's what was wrong and what was changed:

## Problem

After saving preferences, `UpdatePreferencesAsync()` immediately called `WaitForSignedInAsync()`. But clicking "save-preferences" submits an HTML form that POSTs to `/update-line-preferences`, which the server processes and responds with a redirect back to the home page. During this navigation, `Locator("[data-id='sign-out']").WaitForAsync()` threw `TargetClosedException` ("Target page, context or browser has been closed") because the Playwright locator evaluator lost its connection to the frame mid-navigation.

## Fix

Wrapped the `ClickAsync` in `Page.RunAndWaitForNavigationAsync()` — the standard Playwright pattern for actions that trigger navigation:

```csharp
// Before — TargetClosedException during the form POST → redirect navigation
await Navigator.Page.ClickAsync("[data-id='save-preferences']");
var page = new HomePage(Navigator);
await page.WaitForSignedInAsync();

// After — waits for navigation to complete first, then checks the element
await Navigator.Page.RunAndWaitForNavigationAsync(
    async () => await Navigator.Page.ClickAsync("[data-id='save-preferences']"));
var page = new HomePage(Navigator);
await page.WaitForSignedInAsync();
```

`RunAndWaitForNavigationAsync` blocks until the resulting navigation (including any server-side redirects) has fully committed and the page has loaded, so `WaitForSignedInAsync` then finds the sign-out button on the already-loaded page without any race condition.
