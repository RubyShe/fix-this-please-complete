When creating a new file for a non-existent link, `HandleNonExistentMarkdownLinkAsync` always combines the link path with `currentDir`, which means paths that conceptually resolve to a parent directory (e.g. `../notes/note`) will have the new file created under the current document directory instead of the parent directory. In `BrowserNavigationStarting` you already resolve existing files by checking both `currentDir` and its parent, but this creation logic ignores that second case, so the creation location can differ from where an existing file would be found. Consider reusing the same resolved base directory (or `parentDir`) when computing `targetPath` so that `../` and other parent-relative links create files in the expected folder.
