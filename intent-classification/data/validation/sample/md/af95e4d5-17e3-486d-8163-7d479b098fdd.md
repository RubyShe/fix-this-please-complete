fwinstall.sh: resize_rootfs code review fixes (7 changes)
</pr_title>

<pr_description>
Seven targeted fixes to `resize_rootfs()` and the zip re-unarchive path in `fwinstall.sh`, addressing correctness, safety, and output cleanliness issues.

## Changes

- **[Critical] Add `mkfs.ext4` on enlarge path** — after `partprobe`/before post-move `e2fsck`, mirrors what the shrink path already does; without it the subsequent `mount /rootfs` fails on a stale/moved filesystem
- **Scope all locals** — all variables in `resize_rootfs()` now declared `local` to prevent unintended global side-effects
- **Quiet `e2fsck`** — both calls drop `-v -C 0` and redirect to `/dev/null 2>&1`; verbose fsck output was polluting the HTML-formatted user-facing stream
- **`sync` before `e2image`** — flushes write cache after `resize2fs` shrink before the block-level image move
- **Fix `echo` vs `echo -ne`** — `echo "userfs already aligned, "` → `echo -ne` for consistent inline output
- **Validate `label-id`** — instead of copying the label-id dynamically, validate that the disk's existing `label-id` is `0xdeedbeef` (the fixed OpenCCU identifier); return an error if it is not, ensuring `resize_rootfs()` only operates on genuine OpenCCU disks; sfdisk heredocs continue to hard-code `0xdeedbeef`
- **Restart progress indicator on re-unarchive** — zip path was killing the `awk` progress loop before the second `unzip`; restart it with a fresh `PROGRESS_PID` + `trap`




</pr_description>
