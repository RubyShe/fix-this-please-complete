<pr_title>
feat: add `replay` command for rendering unified timeline logs
</pr_title>

<pr_description>
Adds `gh aw replay <run-id-or-url>` — a command that downloads run artifacts and renders a merged, chronological activity timeline to the console, simulating what you'd see watching a Copilot CLI session live.

## What's new

- **`pkg/cli/replay_command.go`** — `NewReplayCommand` / `ReplayWorkflowRun`; accepts the same run ID/URL formats as `audit`, downloads via the existing `downloadRunArtifacts` helper, then feeds the local log dir into `BuildUnifiedTimeline` + `renderUnifiedTimeline`
- **`cmd/gh-aw/main.go`** — registers `replay` in the `"analysis"` group alongside `logs` and `audit`
- **`pkg/cli/replay_command_test.go`** — command structure, stdout output assertions (verifies `agent_turn`, `tool_start`, `tool_done`, server/tool labels present), and empty-dir graceful-warning path

## Example output

```
gh aw replay 12345678

ℹ Unified MCP + Firewall + Agent Event Timeline

Total Events  : 12
  Gateway     : 4  (tool_calls=4, difc_filtered=0, guard_blocked=0)
  Firewall    : 5  (allowed=4, blocked=1)
  Agent       : 3  (turns=1, tool_start=1, tool_done=1)

Event Timeline
╭────────────┬───┬──────────────┬──────────────────────┬────────╮
│Time        │Src│Kind          │Detail                │Status  │
├────────────┼───┼──────────────┼──────────────────────┼────────┤
│10:01:02.000│AG │💬 agent_turn │turn 1                │        │
│10:01:02.120│AG │▶ tool_start  │github/search_code    │        │
│10:01:02.140│GW │🔧 tool_call  │github/search_code    │142ms   │
│10:01:02.145│FW │✓ net_allowed │api.github.com:443    │CONNECT │
│10:01:02.300│AG │■ tool_done   │github/search_code    │success │
╰────────────┴───┴──────────────┴──────────────────────┴────────╯
```

Artifacts are cached in the same directory layout as `logs`/`audit`; re-running against the same run ID reads from disk.
</pr_description>

Done in the latest commit. Colors are now applied via a TTY-guarded `streamColor` helper using the existing `styles` palette:

- **Turn headers** — bold purple (`styles.Command`) with muted timestamp (`styles.LineNumber`)  
- **Tool start** `▶` — yellow (`styles.Progress`)  
- **Tool done** `■` + status — green (`styles.Success`) on success, red (`styles.Error`) on error  
- **Gateway tool call** `🔧` — bold purple (`styles.ServerName`); duration muted, error annotation red  
- **Network allowed** `✓` — cyan (`styles.Info`); HTTP method muted  
- **Network blocked** `✗` + `[blocked]` — red (`styles.Error`); HTTP method muted  
- **DIFC filtered** `🚫` + reason — orange (`styles.Warning`)  
- **Guard blocked** `🛡` + annotation — red (`styles.Error`)  

Colors are suppressed automatically when stdout is not a TTY, keeping piped output clean.
</comment_old>
