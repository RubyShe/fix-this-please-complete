## Problem

The Event Hubs library had several locations where promises could become unhandled, leading to `UnhandledPromiseRejection` errors that crash applications. This was reported in #36230 where `subscription.close()` timeout errors would cause unhandled promise rejections that terminated AWS Lambda functions.

The root cause was that event handlers were declared as `async` functions but registered with rhea-promise which expects `OnAmqpEvent` type: `(context: EventContext) => void`. When async functions are used as event handlers, they return promises that are never awaited, creating dangling promises.

## Changes

### 1. Fixed Event Handlers with Dangling Promises

**connectionContext.ts**
- Wrapped the complex async `onDisconnected` handler in an IIFE (Immediately Invoked Function Expression) with outer `.catch()` to handle any unhandled errors
- Removed unnecessary `async` keyword from `protocolError` and `error` handlers that only perform synchronous logging

**eventHubSender.ts**
- Removed `async` keyword and `await` from `_onAmqpClose` and `_onSessionClose` handlers, making them synchronous functions that start fire-and-forget async operations with proper error handling

**partitionReceiver.ts**
- Changed `onClose` and `onSessionClose` functions to properly `await` the close operations instead of returning the promise
- Wrapped handler invocations with `.catch()` to handle any errors from the async operations

### 2. Modernized Promise Patterns

Converted `getPartitionIds()` methods in both `eventHubProducerClient.ts` and `eventHubConsumerClient.ts` from legacy `.then()` chains to modern `async/await` syntax:

```typescript
// Before
getPartitionIds(options = {}): Promise<Array<string>> {
  return this._context.managementSession!.getEventHubProperties(...)
    .then((eventHubProperties) => eventHubProperties.partitionIds);
}

// After
async getPartitionIds(options = {}): Promise<Array<string>> {
  const eventHubProperties = await this._context.managementSession!.getEventHubProperties(...);
  return eventHubProperties.partitionIds;
}
```

### 3. Enhanced Error Handling in Background Operations

- Added clarifying comments for fire-and-forget background loops in `eventHubBufferedProducerClient.ts` and `batchingPartitionChannel.ts`
- Improved error messages to be more specific about what failed
- Fixed typo: "occured" → "occurred"
- Added final `.catch()` in `util/timerLoop.ts` to handle promise returned from `.finally()`

## Impact

✅ **No Behavior Changes**: All fire-and-forget operations remain fire-and-forget. Changes only add error boundaries to prevent crashes.

✅ **Better Error Handling**: Event handler errors are now properly caught and logged instead of becoming unhandled promise rejections.

✅ **Type Safety**: All event handlers now properly match the `OnAmqpEvent` type signature.

✅ **Minimal Changes**: Only 8 files changed with 133 insertions and 115 deletions.
