Here is a concrete sketch of what the refactor would look like alongside the library's established patterns.

---

## How it maps to existing conventions

The library already uses `ApiItem` as the typed unit of a handler's item store. Each model file defines **one concrete `ApiItem` subclass** per logical entity (e.g. `LightInformation`, `PirSensorConfiguration`, `PortItem`). The `ApiHandler[T]` generic constrains the internal `_items` dict to that type, and typed accessors on the handler class narrow where needed.

The temperature model currently fits that shape except for one issue: a single `TemperatureControlStatus` class carries fields from all three device kinds, gated behind a `device_type` discriminator. Splitting into subclasses removes the discriminator and keeps each class's field set honest, which is exactly what Python dataclass inheritance is for.

---

## Suggested model layout (`axis/models/temperature_control.py`)

```python
# ── shared infrastructure ───────────────────────────────────────────────────

class TemperatureDeviceStatus(enum.StrEnum):
    FAILURE = "failure"
    RUNNING  = "running"
    STOPPED  = "stopped"
    UNKNOWN  = "unknown"

    @classmethod
    def _missing_(cls, value: object) -> TemperatureDeviceStatus:
        return cls.UNKNOWN

# TemperatureDeviceType is retired — class identity carries that information.

# ── base class ───────────────────────────────────────────────────────────────

@dataclass(frozen=True)
class TemperatureDevice(ApiItem):
    """Abstract base for any temperature-managed device."""

    @classmethod
    def decode(cls, data: dict[str, str]) -> Self:          # stays abstract in practice
        raise NotImplementedError

# ── leaf classes ─────────────────────────────────────────────────────────────

@dataclass(frozen=True)
class TemperatureSensor(TemperatureDevice):
    """A temperature-reporting sensor (Sensor.Sx entries)."""

    celsius: float | None = None
    fahrenheit: float | None = None
    name: str | None = None

    @classmethod
    def decode(cls, data: dict[str, str]) -> Self:
        return cls(
            id=data["id"],
            celsius=_to_float(data.get("Celsius")),
            fahrenheit=_to_float(data.get("Fahrenheit")),
            name=data.get("Name"),
        )


@dataclass(frozen=True)
class TemperatureActuator(TemperatureDevice):
    """Shared fields for Heater and Fan devices."""

    intensity: int | None = None
    status: TemperatureDeviceStatus = TemperatureDeviceStatus.UNKNOWN
    status_raw: str | None = None
    time_until_stop: int | None = None

    @classmethod
    def decode(cls, data: dict[str, str]) -> Self:
        status_raw = data.get("Status")
        status, intensity = _parse_status(status_raw)
        return cls(
            id=data["id"],
            intensity=intensity,
            status=status,
            status_raw=status_raw,
            time_until_stop=_to_int(data.get("TimeUntilStop")),
        )


@dataclass(frozen=True)
class TemperatureHeater(TemperatureActuator):
    """A controllable heater (Heater.Hx entries)."""


@dataclass(frozen=True)
class TemperatureFan(TemperatureActuator):
    """A controllable fan (Fan.Fx entries)."""
```

`TemperatureHeater` and `TemperatureFan` are structurally identical today but are distinct VAPIX device categories with separate ID namespaces and future control actions. Leaf classes without extra fields are fine — the library uses the same pattern in the application models (`LoiteringGuard`, `MotionGuard`, etc. all share an `Application` base with minimal per-subclass changes).

The response decoder becomes a factory dispatch:

```python
_DEVICE_FACTORY: dict[str, type[TemperatureDevice]] = {
    "Sensor": TemperatureSensor,
    "Heater": TemperatureHeater,
    "Fan":    TemperatureFan,
}

@classmethod
def decode(cls, bytes_data: bytes) -> GetStatusAllResponse:
    payload = bytes_data.decode("utf-8")
    parsed  = _parse_statusall_entries(payload)
    data: dict[str, TemperatureDevice] = {}
    for prefix, factory in _DEVICE_FACTORY.items():
        for item_id, fields in parsed[prefix.lower()].items():
            data[item_id] = factory.decode(fields)
    return cls(data=data)
```

## Suggested handler layout (`axis/interfaces/temperature_control.py`)

```python
class TemperatureControlHandler(ApiHandler[TemperatureDevice]):
    """Temperature control status for Axis devices."""

    api_id            = ApiId.TEMPERATURE_CONTROL
    default_api_version = API_VERSION
    handler_groups    = (HandlerGroup.API_DISCOVERY,)

    async def _api_request(self) -> dict[str, TemperatureDevice]:
        return await self.get_status_all()

    async def get_status_all(self) -> dict[str, TemperatureDevice]:
        response = await self.vapix.api_request(GetStatusAllRequest())
        return response.data

    # ── narrowed typed accessors ──────────────────────────────────────────

    @property
    def sensors(self) -> dict[str, TemperatureSensor]:
        return {k: v for k, v in self.items() if isinstance(v, TemperatureSensor)}

    @property
    def heaters(self) -> dict[str, TemperatureHeater]:
        return {k: v for k, v in self.items() if isinstance(v, TemperatureHeater)}

    @property
    def fans(self) -> dict[str, TemperatureFan]:
        return {k: v for k, v in self.items() if isinstance(v, TemperatureFan)}

    def get_sensor(self, sensor_id: str) -> TemperatureSensor | None:
        item = self.get(sensor_id)
        return item if isinstance(item, TemperatureSensor) else None

    def get_heater(self, heater_id: str) -> TemperatureHeater | None:
        item = self.get(heater_id)
        return item if isinstance(item, TemperatureHeater) else None

    def get_fan(self, fan_id: str) -> TemperatureFan | None:
        item = self.get(fan_id)
        return item if isinstance(item, TemperatureFan) else None

    @property
    def running_heaters(self) -> dict[str, TemperatureHeater]:
        return {k: v for k, v in self.heaters.items()
                if v.status == TemperatureDeviceStatus.RUNNING}

    @property
    def running_fans(self) -> dict[str, TemperatureFan]:
        return {k: v for k, v in self.fans.items()
                if v.status == TemperatureDeviceStatus.RUNNING}
```

The `isinstance` guards are the library-idiomatic way to narrow `ApiItem` subclasses; they replace the `device_type == TemperatureDeviceType.X` comparisons and are what mypy needs to infer the correct return type on the accessors.

| Handler generic | `ApiHandler[TemperatureControlStatus]` | `ApiHandler[TemperatureDevice]` |
| Accessor return types | `dict[str, TemperatureControlStatus]` | `dict[str, TemperatureSensor]` etc. |
| `isinstance` checks in handler | `item.device_type == …` | `isinstance(item, TemperatureSensor)` |
| `_parse_statusall_entries` | unchanged | unchanged |
| Helper functions | unchanged | unchanged |
