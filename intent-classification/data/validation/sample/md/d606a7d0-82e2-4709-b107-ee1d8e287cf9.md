<pr_title>
✨ Export type-safe rendering utilities and add renderEmail alias

<pr_description>
Addresses issue #4 requesting server-side email rendering with type-safe props instead of API calls. The rendering infrastructure existed but lacked public type exports and had suboptimal naming.

## Changes

**Exports**
- `renderEmail` - alias for `renderEmailComponent` (clearer naming)
- `render` - direct component rendering for advanced cases
- `ExtractComponentProps<T>` - utility type for extracting component prop types
- `RenderOptions` - options interface

**Documentation**
- Added type-safe rendering patterns to usage guide
- Examples showing generic type parameter usage

## Usage

Basic rendering (unchanged):
```ts
const html = await renderEmail('WelcomeEmail', { userName: 'John' })
```

Type-safe rendering with prop validation:
```ts
type WelcomeProps = { userName: string; confirmationUrl: string }

const html = await renderEmail<WelcomeProps>('WelcomeEmail', {
  userName: body.userName,        // TypeScript validates these
  confirmationUrl: body.url,
})
```

Email template with typed props:
```vue
<script setup lang="ts">
interface Props {
  userName: string
  confirmationUrl: string
}
const { userName, confirmationUrl } = defineProps<Props>()
</script>
```

All existing code remains compatible - `renderEmailComponent` continues to work as before.
