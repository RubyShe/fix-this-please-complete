## Summary

Here's what I found and fixed:

### Root Cause
All failures on Ubuntu Linux showed `TargetClosedException: Target page, context or browser has been closed` from Playwright. This is caused by **Chromium renderer process crashes due to limited `/dev/shm` (shared memory)** on GitHub Actions Ubuntu runners.

**Evidence from artifact analysis:**
- Every failure on Linux is a `TargetClosedException` — different tests fail randomly each run (twitter, apple, google, chromium null channel, chrome channel)
- Firefox tests **never** fail — Firefox doesn't use `/dev/shm` the same way Chromium nt on those platforms
- Multiple workflow runs required 6–12 re-attempts before passing (`run_number: 8099` needed **8 attempts**)
- Trace analysis confirmed that 3+ seconds of server-side processing during Alexa token deletion coincides with browser crashes

### Changes Made

**`BrowserFixture.cs`** — Added `--disable-dev-shm-usage` to Chromium launch options on Linux:
```csharp
else if (OperatingSystem.IsLinux() && Options.BrowserType == BrowserType.Chromium)
{
    // ...
    options.Args = ["--disable-dev-shm-usage"];
}
```
This tells Chrome to use `/tmp` instead of `/dev/shm`, bypassing the shared memory size limitation. Scoped to Linux + Chromium only (Firefox and other platforms unaffected).

**`PreferencesTests.cs`** — Replaced two `Task.Delay(TimeSpan.FromSeconds(1), TestContext.Current.CancellationToken)` calls with `await page.WaitForLinesAsync()`. Trace analysis confirmed the line preference elements appear ~80ms after the sign-out button, so a Playwright selector wait is both more reliable and faster than a fixed 1-second delay.

### Security Summary
No security vulnerabilities were introduced or found. The `--disable-dev-shm-usage` flag has no security implications — it only changes which filesystem location Chrome uses for shared memory. (The initially considered `--no-sandbox` flag was not included as it would unnecessarily weaken the browser's security sandbox.)
