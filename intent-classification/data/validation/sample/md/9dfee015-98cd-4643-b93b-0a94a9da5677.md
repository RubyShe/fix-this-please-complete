Fixed in commit `f9aed32`. Three changes to ensure `*Selection` states appear in the YAML and diagrams:

1. **`resolveChildStates()` post-processing** — after AST traversal completes, this new function checks every composite state's `initial_child` field. If the referenced child (e.g. `TaskSelection`, `MovementSelection`) is not yet in `g_states`, it adds a stub entry with the correct `parent` and `is_choice = true` (detected by the `*Selection` naming convention). This is the primary fix for the case where the AST visitor misses the state definition.

2. **Single non-list reaction extraction** — `extractReactionsFromDecl` now handles `using reactions = boost::statechart::custom_reaction<E>` (not wrapped in `mpl::list`) in addition to `boost::mpl::list<...>`. Previously only `mpl::list` reactions were extracted, so `TaskSelection`/`MovementSelection` showed no reactions.

3. **Stub overwrite** — `processState` now overwrites a stub entry (one with empty reactions) when the real class definition is visited, ensuring the full info takes priority if the primary path does succeed.
</comment_old>
