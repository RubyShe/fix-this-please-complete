## Summary

This PR replaces the Blazor WebAssembly DevServer with the Blazor Gateway in the standalone WASM template, and leverages the SDK's built-in `StaticWebAssetSpaFallbackEnabled` property instead of the custom `SpaFallback.targets`.

## Changes

### Commit 1: Remove ThreadingApp and multi-threading testing support
Multi-threading is not currently supported. Removes ThreadingApp, ThreadingApp.Server, associated test files, and the multi-threading helper infrastructure.

### Commit 2: Use SDK StaticWebAssetSpaFallbackEnabled instead of custom SpaFallback.targets
- Deletes `src/Components/WebAssembly/testassets/SpaFallback.targets`
- Adds `StaticWebAssetSpaFallbackEnabled=true` to StandaloneApp and the benchmark TestApp
- The SDK now generates `{**fallback:nonfile}` endpoints in the manifest at build time

### Commit 3: Remove MapFallbackToFile from BlazorGateway
Since the SPA fallback is now handled via the static web assets endpoints manifest (served by `MapStaticAssets`), the Gateway no longer needs to call `MapFallbackToFile`.

### Commit 4: Update WASM template to use Blazor Gateway instead of DevServer
- Replaces `Microsoft.AspNetCore.Components.WebAssembly.DevServer` with `Microsoft.AspNetCore.Components.Gateway`
- Adds `OverrideHtmlAssetPlaceholders` and `StaticWebAssetSpaFallbackEnabled` properties

## Dependencies

Requires SDK fix: https://github.com/dotnet/sdk/pull/54353

## Testing

- Built repo successfully
- Verified StandaloneApp E2E with Gateway + SPA fallback
- Verified instantiated blazorwasm template E2E with patched SDK
