fix: DbSessionAdapter.clear_session must purge persisted messages
</pr_title>

<pr_description>
## Bug and impact

`DbSessionAdapter.clear_session()` only cleared the in-memory `_history_cache`. Callers such as `BotSessionManager._save_history()` use **clear + rewrite** to trim history. Persisted messages in the database were never removed, so `on_agent_start()` reloaded the full old history after a process restart or a new adapter instance.

**User impact:** DB-backed bots and managed agents appeared to trim/clear chat history in-process, but stale messages came back on reload—wrong context for the LLM and possible privacy issues (cleared messages resurfacing).

## Root cause

`clear_session` did not call `conversation.delete_messages()` (when available) and did not reset `_sessions` / hydration from `on_agent_start`, so appended DB rows accumulated across trim operations.

## Fix

- Purge persisted messages via `conversation.delete_messages(session_id, None)` when the DB exposes a conversation store
- End active session with `on_agent_end` before reset
- Track cleared sessions so the next `on_agent_start` does not repopulate cache from stale DB rows

## Validation

- Repro script confirmed stale reload before fix
- `tests/managed/test_managed_persistence.py::TestDbSessionAdapter::test_clear_session_purges_db_history`
- Existing `tests/unit/session/test_session_store.py` race tests still pass

## Recent scan context

Commits #1724–#1727 fixed analogous TOCTOU issues on `DefaultSessionStore` (file-backed). This closes the same class of bug for the DB-backed adapter path.
