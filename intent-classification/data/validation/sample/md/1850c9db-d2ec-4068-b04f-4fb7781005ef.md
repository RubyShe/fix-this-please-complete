<pr_title>
Fix ls command execution context in CI workflow
</pr_title>

<pr_description>
The CI workflow was executing `ls -la $model_path` on the host runner before running the Docker container inference test. When the `/models` directory doesn't exist, `model_path` is set to a HuggingFace model identifier (e.g., `amd/Llama-3.3-70B-Instruct-MXFP4-Preview`), which only exists inside the container after download, causing the `ls` command to fail.

## Changes

- Move `ls` command inside the Docker container execution block where the model path is actually accessible
- Add informative fallback message when model doesn't exist yet (before HuggingFace download)

```yaml
# Before: runs on host
echo "Model path: $model_path"
ls -la $model_path || true
docker exec atom_test bash -lc "python3 -m atom.examples.simple_inference..."

# After: runs inside container
echo "Model path: $model_path"
docker exec atom_test bash -lc "
  ls -la \"$model_path\" || echo \"Model path does not exist yet (will be downloaded by HuggingFace)\"
  python3 -m atom.examples.simple_inference...
"
```

This ensures the debug output runs in the same context where the model will be accessed, providing accurate diagnostics regardless of whether `/models` is pre-mounted or models are downloaded on-demand.
</pr_description>
