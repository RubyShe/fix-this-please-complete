Code review of the GrapesJS project identified several bugs affecting component rendering and styling.

### Fixed Issues

- **Invalid SVG namespace URLs** (`const.js`): `xmlns="http =//..."` → `xmlns="http://..."` in IconLock, IconEvent, PcfIcon, IconClick constants
- **Class name mismatch** (`richtextbox.js`): Component declared `DDBRichTextBox` but isComponent checks for `DDBControlRichTextBox`
- **Orphan closing tags** (`label.js`, `button.js`, `optionset.js`): Removed stray `</span>` tags with no matching opener
- **Style syntax** (`traits.js`): `style.backgroundColor = 'gray;'` → `'gray'` (semicolons invalid in JS style values)
- **View name separator** (`subgrid.js`, `chart.js`): Multiple view names concatenated without delimiter; added `, ` separator

### Example

Before:
```javascript
// const.js - broken SVG
export const IconLock = `<svg xmlns="http =//www.w3.org/2000/svg">...`;

// traits.js - invalid style syntax  
input.style.backgroundColor = 'gray;';
```

After:
```javascript
export const IconLock = `<svg xmlns="http://www.w3.org/2000/svg">...`;

input.style.backgroundColor = 'gray';
```




</pr_description>

The `-2` is needed because I changed the separator from nothing to `, ` (comma + space = 2 characters). 

Original code:
```javascript
viewnames += `${await Crm.GetViewName(...)}`;  // no separator
viewnames.substring(0, viewnames.length - 1);  // removes last char of last name (bug)
```

My fix:
```javascript
viewnames += `${await Crm.GetViewName(...)}, `;  // adds ", " separator
viewnames.substring(0, viewnames.length - 2);   // removes trailing ", "
```

The original `-1` was actually a bug since no trailing character was being added - it would incorrectly truncate the last view name. If you'd prefer to keep the original behavior without a separator, I can revert this change.
