**Summary of Changes:**

**Root Cause:** In `append()` in `template.js`, the condition `hydrate_node?.parentNode === dom` only detected when `hydrate_node` was a *direct child* of `dom`. When a layout component (like `docs-layout.ripple`) contained children with nested `if`/`for` blocks, those blocks would leave `hydrate_node` pointing to a node deep inside the layout's root element (e.g., an `<!--]-->` HYDRATION_END comment inside `<main>`). Since `hydrate_node.parentNode` was `<main>` (not `<div.layout>`), the check failed and the code incorrectly updated `branch.s.end` to that deep internal node.

This caused two downstream problems when HMR fired:
1. `remove_block_dom(s.start, s.end)` traversed siblings from the layout's div, but `s.end` was a deep internal node — it removed unrelated elements including the root `<!--]-->` hydration marker
2. `target = hydrate_node` in `hmr.js` captured `null` (after `hydrate_advance()` on a leaf node), so new HMR content was inserted at the wrong DOM location — outside the CSS container, appearing "zoomed"

**Fix:** One line change — `hydrate_node?.parentNode === dom` → `hydrate_node !== null && hydrate_node !== dom && dom.contains(hydrate_node)`. This is already the pattern used in the `anchor === dom` branch above it. The fix correctly resets `hydrate_node` to `dom`'s sibling level regardless of how deep inside `dom` the cursor was nested.

<pr_title>
Fix HMR "zoom" issue caused by deep hydrate_node not being reset in append()
</pr_title>

<pr_description>
After hydrating a layout component whose children contain `if`/`for` blocks, `hydrate_node` could be left pointing to a node deep inside the layout's root element. The `append()` check `hydrate_node?.parentNode === dom` only caught **direct** children — missing grandchildren and deeper nodes — so `pop(dom)` was never called, corrupting the branch state.

This caused two problems when HMR fired:
1. `branch.s.end` was set to a deep internal node (e.g. a `<!--]-->` marker inside `<main>`), so `remove_block_dom()` traversed siblings from the layout div until it hit `null`, removing unrelated DOM including the root hydration end marker.
2. `target = hydrate_node` in `hmr.js` captured `null` (after `hydrate_advance()` on a leaf), inserting new content outside its CSS container — the "zoom" effect.

## Changes

- **`template.js` — `append()`**: Replace `hydrate_node?.parentNode === dom` with `dom.contains(hydrate_node)`, consistent with the `anchor === dom` branch directly above it that already used `dom.contains()`. This resets the cursor to `dom`'s sibling level regardless of nesting depth.

```js
// Before — only catches direct children of dom
if (hydrate_node?.parentNode === dom) {
    pop(dom);
}

// After — catches dom descendants at any depth
if (hydrate_node !== null && hydrate_node !== dom && dom.contains(hydrate_node)) {
    pop(dom);
}
```

- **New hydration test** (`tests/hydration/hmr.ripple` + `hmr.test.js`): covers the layout-with-nested-children pattern that triggered the bug.
