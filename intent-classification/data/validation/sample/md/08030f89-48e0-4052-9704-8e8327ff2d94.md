<pr_title>
Fix repo-root-relative import path resolution in `ResolveIncludePath`
</pr_title>

<pr_description>
`imports: [.github/agents/planner.md]` was broken because `ResolveIncludePath` unconditionally joined import paths onto `baseDir` (`.github/workflows/`), producing `.github/workflows/.github/agents/planner.md` — a path that never exists.

## Changes

- **`pkg/parser/remote_fetch.go` / `remote_fetch_wasm.go`**: Before resolving, detect repo-root-relative paths and adjust the resolution base accordingly:
  - `.github/`-prefixed → resolve from repo root; security scope stays `.github/`
  - `/`-prefixed → strip leading slash, resolve from repo root; security scope is repo root (still blocks traversal above it)
  - All other paths → unchanged behavior (resolved relative to `baseDir`)

- **`pkg/parser/frontmatter_utils_test.go`**: Added test cases covering `.github/agents/` imports, `/`-prefixed repo-root imports, backward-compat relative imports, and path traversal rejection for both new code paths. Also added `TestResolveIncludePath_DotGithubRepo` verifying all three resolution rules and traversal rejection work correctly when the repository itself is named `.github` (e.g. an org's `org/.github` repo), where the on-disk layout is `<parent>/.github/.github/workflows/`.

## Example

```yaml
# Previously failed (resolved to .github/workflows/.github/agents/planner.md)
imports: [.github/agents/planner.md]

# Now resolves correctly to <repo-root>/.github/agents/planner.md
# Also supported:
imports: [/agents/agent.md]  # resolves to <repo-root>/agents/agent.md
```

&gt; [!WARNING]
&gt; The security scope for `/`-prefixed paths is currently the entire repo root. A follow-up may restrict this to only `.github/` and `.agents/` subdirectories — feedback is pending on the intended security boundary.
</pr_description>
