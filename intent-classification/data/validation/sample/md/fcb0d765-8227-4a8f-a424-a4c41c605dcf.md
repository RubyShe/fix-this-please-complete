## Summary

The `ckb-instrument` crate failed to compile during `cargo publish` because `progress_bar` is an optional feature (not enabled by default), but several code paths assumed it was always available.

### Changes Made

**`util/instrument/src/export.rs`** — Split the iterator chain so `.progress_with()` is only called when the feature is enabled:
```rust
let iter = chunk.collect::<Vec<_>>().into_par_iter();
#[cfg(feature = "progress_bar")]
let iter = iter.progress_with(progress_bar_clone.clone());
iter.try_for_each(...)
```

**`util/instrument/src/import.rs`** — Removed the `#[cfg(feature = "progress_bar")]` gate from the `read_from_json` method itself (so it always exists), and instead gated only the progress bar creation and usage within the method body:
- Progress bar creation (`ProgressBar::new(...)`) — gated with `#[cfg(feature = "progress_bar")]`
- Verify callback — two versions: one with progress bar increment, one without
- `progress_bar.finish_with_message("done!")` — gated with `#[cfg(feature = "progress_bar")]`

This fixes all 3 compilation errors and 8 unused import warnings from the original issue.

### Security Summary
No security vulnerabilities were introduced. The changes are purely conditional compilation (`#[cfg]`) annotations with no new logic, dependencies, or external input handling.
