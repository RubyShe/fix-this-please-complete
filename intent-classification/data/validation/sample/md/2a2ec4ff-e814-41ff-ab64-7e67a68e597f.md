`connectFailure` can throw `TimeoutException` and `InterruptedException` from `Future#get(...)` but only catches `ExecutionException`. This can make the test fail for the wrong reason (e.g., timeouts under load) and, in the interrupted case, can swallow the interrupt. Handle `TimeoutException` (return it or unwrap as appropriate) and catch `InterruptedException` while restoring the thread interrupt flag (`Thread.currentThread().interrupt()`), then return the exception so assertions can be explicit.
