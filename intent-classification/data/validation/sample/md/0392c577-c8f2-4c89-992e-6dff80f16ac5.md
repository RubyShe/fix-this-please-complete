<pr_title>
Implement MOUNT/IMGMOUNT batch commands, FAT12 floppy support, and MSCDEX architecture rework
</pr_title>

<pr_description>
### Description of Changes

**CodeQL fixes:**
- `CdRomDrive.GetTrackInfo`: implicit-filter foreach → `FirstOrDefault`
- `CueBinImage.FindFirstDataTrack` + `FindTrack`: implicit-filter foreach → `FirstOrDefault`
- `CueSheetParser`: foreach mapping `rawLine → line.Trim()` → `.Select()`; `Path.Combine` with possible rooted second argument → `Path.GetFullPath(raw, cueDir)`
- `MscdexService.GetNumberOfCdRomDrives`: both-branch assignment → direct initialisation; `TryGetDrive`/`TryGetDriveByLetter` implicit-filter foreach → `FirstOrDefault`

**MSCDEX architecture rework:**
- `MscdexService` is now owned and constructed by `Dos` (before `ProcessManager`), not injected from outside
- `Dos` implements `Spice86.Shared.Interfaces.IDriveStatusProvider` — the UI always polls, no events are emitted
- New shared types: `DosVirtualDriveType` enum, `DosVirtualDriveStatus`, `IDriveStatusProvider` interface (all in `Spice86.Shared`)

**FAT12 floppy image support (TDD-first):**
- `BiosParameterBlock` — parses the BIOS Parameter Block from a 512-byte FAT12 boot sector
- `FatDirectoryEntry` — parses 32-byte directory entries (file / directory / volume-label / deleted)
- `Fat12FileSystem` — reads cluster chains, lists the root directory, and reads file data from an image
- `FloppyDiskDrive` — extended with `MountImage()`, `HasImage`, and `GetFileSystem()`
- `DosDriveManager` — new methods: `MountFloppyImage()`, `MountFloppyFolder()` (with debug logging), `MountFolderDrive()`, `TryGetFloppyDrive()`, `FloppyDrives`
- `DosFileManager` — added floppy-image file-open code path

**MOUNT / IMGMOUNT batch commands:**
- `MOUNT <drive> <path> [-t hdd|floppy]` — mounts a host folder as a DOS drive letter
- `IMGMOUNT <drive> <image> [-t floppy|iso|cue]` — mounts a disk image; extension is auto-detected (`.img`/`.ima`/`.vfd` → floppy, `.iso` → ISO, `.cue` → CUE/BIN)
- Both commands wired into `BatchCommandHandlers` and `DosBatchExecutionEngine`

**UI drive status indicators (polling):**
- `DriveStatusViewModel` — polls `IDriveStatusProvider.GetDriveStatuses()` every second; rebuilds the observable collection only when content changes
- `DriveStatusUserControl` — AXAML status-bar control showing one pill-shaped indicator per mounted drive
- `MediaPresenceBrushConverter` — green/grey brush based on the media-present flag
- `MainWindow.axaml` — new drive status bar item, hidden when no `DriveStatusViewModel` is set

### Rationale behind Changes

The original PR introduced a `MscdexService` as an externally-injectable dependency, but the maintainer clarified that MSCDEX must be owned by `Dos` and exposed through a `Spice86.Shared` polling interface rather than events. This rework aligns the architecture with that principle.

FAT12 floppy image support was requested to complete the drive-abstraction story alongside CD-ROM and host-folder drives, mirroring DOSBox Staging's `IMGMOUNT` capability for floppy images.

The `MOUNT` and `IMGMOUNT` batch commands make the drive-mounting functionality available inside the emulated DOS environment (e.g., from `AUTOEXEC.BAT`), consistent with how DOSBox Staging exposes these commands.

The UI drive status bar uses polling rather than events to remain consistent with the pattern established by other `DispatcherTimer`-based ViewModels in the codebase (`CpuViewModel`, `PaletteViewModel`, etc.).

### Suggested Testing Steps

1. **Floppy image mount via IMGMOUNT:**
   - Add `IMGMOUNT A myFloppy.img -t floppy` (or `.ima` / `.vfd`) to `AUTOEXEC.BAT`
   - Verify the drive appears in the status bar and files on the image are accessible from DOS

2. **Folder mount via MOUNT:**
   - Add `MOUNT D /path/to/host/folder` to `AUTOEXEC.BAT`
   - Verify `D:` is accessible from the emulated DOS prompt

3. **CD-ROM image mount via IMGMOUNT:**
   - Add `IMGMOUNT D game.cue -t cue` or `IMGMOUNT D game.iso` to `AUTOEXEC.BAT`
   - Verify the drive appears in the status bar with the correct volume label

4. **Drive status bar:**
   - Launch with any mounted drive and confirm the status bar shows a labelled pill for each drive
   - Indicators should update within one second of a mount/unmount event

5. **Unit tests:**
   - `dotnet test tests/Spice86.Tests/Spice86.Tests.csproj` — all 1 792 tests must pass
   - Key test classes: `BiosParameterBlockTests`, `FatDirectoryEntryTests`, `Fat12FileSystemTests`, `DosDriveManagerFloppyTests`, `MountBatchCommandTests`
