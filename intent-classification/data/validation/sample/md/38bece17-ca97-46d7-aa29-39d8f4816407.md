<pr_description>
## Summary

Adds automatic mounting of MCP servers as local CLI tools in agentic workflows. This behavior is opt-in via a new `tools.mount-as-clis: true` flag (default `false`). When enabled, all user-facing MCP servers — including built-in ones like `github` and `playwright` as well as custom servers — are exposed as standalone shell commands and excluded from the agent's final MCP config so the agent uses the CLI wrappers exclusively. When `false`, no CLI mounting step is emitted and no prompt section is injected.

## How It Works

After the MCP gateway starts, a new "Mount MCP servers as CLIs" workflow step runs `mount_mcp_as_cli.cjs` via `actions/github-script`. This script:

1. Reads a manifest of configured MCP servers (saved by `start_mcp_gateway.sh` before cleanup)
2. For each server, follows the full MCP session protocol (`initialize` → `notifications/initialized` → `tools/list`) to discover available tools
3. Generates a standalone CLI wrapper script at `${RUNNER_TEMP}/gh-aw/mcp-cli/bin/<server-name>`
4. Locks the bin directory (`chmod 555`) so the agent cannot modify or add scripts
5. Adds the directory to `PATH` via `core.addPath()` for subsequent steps

The agent is also informed about these tools via an injected prompt section (wrapped in `<mcp-clis>` XML tags) listing the available CLI commands.

### Architecture: Gateway vs. Agent Config

The MCP gateway must start Docker containers for **all** configured servers — including CLI-mounted ones — so they have reachable endpoints for the CLI manifest. The filtering is therefore applied in two stages:

1. **Gateway config** (piped to `start_mcp_gateway.sh`): includes all servers so the gatewnfig` (parsed from `tools.mount-as-clis`, default `false`)

## Example

For a workflow configured with `mount-as-clis: true`, `playwright`, `github`, and a custom `tavily` MCP server, the agent will have:

```bash
# Shell commands available on PATH (under ${RUNNER_TEMP}/gh-aw/mcp-cli/bin/):
playwright --help
playwright browser_navigate --url https://example.com
github issue_read --method get --owner octocat --repo Hello-World --issue_number 1
tavily search --query "latest AI news"
```

Those servers are **excluded from the agent's MCP config**, so the agent interacts with them exclusively through the CLI wrappers. The gateway still starts all Docker containers so the CLI wrappers can communicate with them.
