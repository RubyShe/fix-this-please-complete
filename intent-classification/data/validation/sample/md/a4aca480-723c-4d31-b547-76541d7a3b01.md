<pr_title>
Fix unbounded stack recursion in DefaultBinaryExpr.evaluate() across distinct operator types
</pr_title>

<pr_description>
`DefaultBinaryExpr.evaluate()` recursed one JVM frame per cross-operator-type boundary. `flattenChain()` already handles same-operator chains iteratively, but operands of a *different* operator type (e.g. the `*` inside `1 + (2 * ...)`) fell through to a direct recursive `evaluate()` call. With ~10 000 nesting levels this produces `StackOverflowError`.

## Changes

### `DefaultBinaryExpr` — iterative evaluator
Replaced implicit recursion with a two-`Stack` post-order traversal:
- **`evaluate(Context)`** expands each `DefaultBinaryExpr` via `flattenChain()`, pushes an `EvalFrame` sentinel plus operand `Expr`s onto a work stack, and evaluates non-binary leaves immediately onto a result stack. When an `EvalFrame` fires it splices its operands' results and delegates to `evaluateChain()`.
- **`evaluateChain(List<Object>, Context)`** — new `protected abstract` method. Receives already-evaluated operand values; each subclass moves its operator logic here instead of in `evaluate()`.
- **`EvalFrame`** — private static inner class carrying the owner node and operand count.
- Uses `java.util.Stack` (Java 1.5 compatible; `ArrayDeque`/`Deque` require 1.6+).

```java
// Before: each different-type operand recurses
public Object evaluate(Context context) throws JaxenException {
    List operands = flattenChain();
    ...
    for (int i = ...) {
        result += operands.get(i).evaluate(context);  // recursion if operand is DefaultBinaryExpr of different type
    }
}

// After: fully iterative via work/result stacks
public Object evaluate(Context context) throws JaxenException {
    Stack workStack = new Stack();
    Stack resultStack = new Stack();
    workStack.push(this);
    while (!workStack.isEmpty()) { ... }  // no recursion across operator types
    return resultStack.pop();
}
```

### All 11 `DefaultBinaryExpr` subclasses
`evaluate()` renamed to `evaluateChain(List<Object>, Context)` in: `DefaultPlusExpr`, `DefaultMinusExpr`, `DefaultMultiplyExpr`, `DefaultDivExpr`, `DefaultModExpr`, `DefaultAndExpr`, `DefaultOrExpr`, `DefaultEqualityExpr` (abstract), `DefaultRelationalExpr` (abstract), `DefaultUnionExpr`.

### `OverflowTest` — new `testDeepMixedOperators`
Builds a 10 000-level right-associative alternating `and`/`or` tree via `DefaultXPathFactory` (programmatic, not parsed — the XPath parser's grammar descent also recurses per parenthesis level, so string-parsing at this depth would overflow independently). Evaluates with a minimal `ContextSupport`+`DocumentNavigator` context.
</pr_description>
