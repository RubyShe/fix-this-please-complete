<pr_title>
[Server/Client] Support RSAEncryptedSecret format for UserNameIdentityToken with legacy .NET compatibility
</pr_title>

<pr_description>
## Proposed changes

This PR now covers full SDK handling for RSA username tokens by adding both server-side **decryption** and client-side **encryption** support for `RsaEncryptedSecret` (UA 1.05), while preserving legacy RSA behavior for compatibility.

- **Server token format support**
  - `UserNameIdentityTokenHandler.Decrypt(...)` accepts RSA `RsaEncryptedSecret` payloads.
  - Legacy RSA `EncryptedData` decryption remains as fallback.
  - `RsaEncryptedSecret` DataType usage now pulls from global constants (`DataTypeIds.RsaEncryptedSecret`) instead of local numeric constants.

- **Client token format support**
  - `UserNameIdentityTokenHandler.Encrypt(...)` now applies RSAEncryptedSecret based on password size for RSA policies:
    - `password.Length > 64` bytes → serialize as `RsaEncryptedSecret`
    - `password.Length <= 64` bytes → keep legacy RSA `EncryptedData` format

- **Validation and cryptographic flow**
  - Validates ExtensionObject type/encoding, SecurityPolicy URI, certificate hash, signing timestamp window, signature, and nonce.
  - Decrypts `KeyData`, derives signing/encryption/IV material, decrypts payload, and securely clears sensitive intermediate buffers.

- **Legacy target compatibility follow-up**
  - Added local compatibility helpers in `UserNameIdentityTokenHandler` to avoid APIs unavailable on older targets:
    - Replaced direct `CryptographicOperations.ZeroMemory(...)` calls with a helper that uses:
      - `CryptographicOperations.ZeroMemory` on `NET8_0_OR_GREATER`
      - `Array.Clear` on earlier targets
    - Replaced `SHA1.HashData(...)` with a compatible helper based on `SHA1.Create().ComputeHash(...)`
  - This resolves the CodeQL/build failures seen on older target frameworks (e.g., `net48`, `net472`, `netstandard2.1`) without changing protocol behavior.

- **Focused test coverage**
  - Added and extended `UserNameIdentityTokenHandlerTests` to cover:
    - RSAEncryptedSecret decrypt path
    - Legacy RSA decrypt compatibility
    - Encrypt behavior for short, threshold (64), and long passwords
    - Encrypt/decrypt roundtrip validation for both legacy and RSAEncryptedSecret paths
