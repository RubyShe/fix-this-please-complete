<pr_title>
Add </pr_title>`compatibility_version` DSL to Formula class
<pr_description>
Implements a new </pr_description>`compatibility_version` DSL for Homebrew formulae to help minimize unnecessary dependency upgrades when changes are backwards-compatible.

## Overview

This PR adds support for formula maintainers to declare API/ABI compatibility levels using a new `compatibility_version` field. When a formula has a specific `compatibility_version`, dependents don't need to be upgraded as long as the installed version has the same compatibility level.

## Changes

### New DSL Method

Formulae can now declare a `compatibility_version`:

```ruby
class ExampleLib < Formula
  desc "Example library"
  homepage "https://example.com"
  url "https://example.com/lib-1.0.tar.gz"
  
  # Indicates API/ABI compatibility level
  compatibility_version 1

  def install
    system "./configure", "--prefix=#{prefix}"
    system "make", "install"
  end
end
```

When upgrading from version 1.0 → 1.1 → 1.2 with the same `compatibility_version 1`, dependents won't need to be rebuilt. When the API/ABI changes incompatibly (e.g., version 2.0), bump to `compatibility_version 2`.

### Storage and Tracking

The `compatibility_version` is stored in:
- The formula's `INSTALL_RECEIPT.json` in `source.versions.compatibility_version`
- Runtime dependencies for each dependent formula
- Formula serialization via `to_hash`

### Dependency Resolution

Updated `Dependency#installed?` to check `compatibility_version` when determining if an upgrade is needed:
- If both installed and required formulae have matching `compatibility_version`, the dependency is satisfied
- Falls back to existing version/revision checking if compatibility versions don't match or are unset

### Implementation Details

- Optional field (returns `nil` if not set) for back is bumped whenever needed
2. `compatibility_version` is _not_ bumped when a bump is not needed

To do the above, we would likely need to run the following dependent tests (or something similar to them):

If `compatibility_version` is bumped, we need to check that each dependent is broken when using the previous `compatibility_version`, but is not broken under the newer `compatibility_version`.

If `compatibility_version` is _not_ bumped, then we need to check that each dependent still works when using the oldest bottles that have the same `compatibility_version`.

### What is the motivation for the feature?

This should help minimise the number of formulae that `brew {install,upgrade} foo` needs to upgrade to ensure that user installs are not broken.

### How will the feature be relevant to at least 90% of Homebrew users?

This should help address a pain point that many users have expressed many times over the years.

### What alternatives to the feature have been considered?

Doing nothing.
