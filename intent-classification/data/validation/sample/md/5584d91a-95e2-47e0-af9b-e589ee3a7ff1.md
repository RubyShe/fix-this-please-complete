## Problème

Les partenaires envoient parfois des titres d'offres avec des entités HTML déjà encodées, par exemple :

```
alternance 12 mois – technicien.ne d'études in vitro &amp; in vivo F/H
```

`sanitizeTextField` décodait `&amp;` → `&` via `he.decode`, puis `sanitizeHtml` ré-encodait `&` → `&amp;`. Résultat : la valeur stockée en base contenait `&amp;`, affiché littéralement sur le front partout où `offer_title` est rendu comme texte brut (aria-labels, cellules tableau, etc.).

## Changements

- **`sanitizeTextField`** : quand `keepFormat=false`, décode les entités HTML en sortie (`he.decode` après `sanitizeHtml`). La sémantique est maintenant claire : `keepFormat=false` → texte brut, `keepFormat=true` → HTML-safe pour `dangerouslySetInnerHTML`. La sanitization XSS reste intacte (`sanitizeHtml` strip les balises dangereuses avant le decode final).
- **`formatTextFieldsJobsPartners`** : `offer_title` et `workplace_name` passent à `keepFormat=false` — ce sont des champs texte brut, sans HTML formaté.
- **Migration** : décode les entités HTML dans `offer_title` et `workplace_name` directement dans la collection `jobs_partners` pour corriger les données existantes.
- **Tests** : mis à jour pour refléter la nouvelle sémantique de `keepFormat=false`.
