## Current State (Not Implemented)

The iOS app has a NodeDB reset button in `DeviceConfig.swift` but it's incomplete vs. the design spec:

1. **No "Preserve Favorites" toggle** — the confirmation dialog is a plain `confirmationDialog` with a single destructive button.
2. **Always preserves favorites on-device** — `sendNodeDBReset` hardcodes `adminPacket.nodedbReset = true` (the protobuf bool meaning "preserve favorites = true"), so there's nirmationDialog` on the "Reset NodeDB" button with a **Sheet** (SwiftUI `confirmationDialog`/`alert` don't support custom views) that shows:
>   - A description of the reset action
>   - `Toggle("Preserve Favorites", isOn: $preserveFavorites)` defaulting **on**
>   - Destructive "Reset" and "Cancel" buttons
> - Pass `preserveFavorites` to `sendNodeDBReset` and `clearDatabase`
>
> **2. `Meshtastic/Accessory/Accessory Manager/AccessoryManager+ToRadio.swift`**
> - Update `sendNodeDBReset(fromUser:toUser:)` to accept `preserveFavorites: Bool`
> - Replace hardcoded `adminPacket.nodedbReset = true` with `adminPacket.nodedbReset = preserveFavorites`
>
> **3. `Meshtastic/Persistence/UpdateSwiftData.swift`**
> - Update `clearDatabase(includeRoutes:)` to add `preserveFavorites: Bool = false`
> - When `preserveFavorites == true`, skip deletion of `NodeInfoEntity` records where `favorite == true`
>
> **Acceptance Criteria:**
> - [ ] "Reset NodeDB" opens a sheet/dialog with a "Preserve Favorites" toggle (default: on)
> - [ ] Toggle **on** → sends `nodedbReset = true`, retains `NodeInfoEntity` where `favorite == true` locally
> - [ ] Toggle **off** → sends `nodedbReset = false`, fully clears all nodes locally (current behaviour)
> - [ ] Factory Reset flow is unaffected
> - [ ] All existing tests pass
>
> **References:** meshtastic/protobufs#791 · https://github.com/meshtastic/design/issues/37
