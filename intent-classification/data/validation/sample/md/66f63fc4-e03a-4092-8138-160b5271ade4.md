<pr_description>
Implements internal-data-only product enrichment guardrails to ensure AI agents never generate content without company-owned source data, as defined in the integration strategy.

## Changes Made

### New: `lib/src/holiday_peak_lib/agents/guardrails/`

- **`EnrichmentGuardrail`** — middleware class that enforces the internal-data-only enrichment policy:
  - `validate_sources()` — checks PIM (product catalog) and ACP/DAM content; rejects stub/placeholder responses that contain no real company-owned data
  - `tag_content()` — annotates enriched dicts with a `_sources` attribution list (e.g. `["pim:SKU-001", "acp:SKU-001"]`)
  - `log_audit()` — emits structured audit log entries (INFO on approval, WARNING on rejection) for data lineage tracking
- **`SourceValidationResult`** — dataclass carrying `is_valid`, `source_ids`, and `rejection_reason`
- Exported from `holiday_peak_lib.agents` package

### Updated: `apps/ecommerce-product-detail-enrichment`

- `ProductDetailEnrichmentAgent.handle()` now applies the guardrail after fetching source data:
  - Returns `{"error": "enrichment not available", "reason": "..."}` when no PIM or real ACP data exists for the SKU
  - All enriched responses include a `_sources` attribution field
  - Every enrichment attempt (approved or rejected) is recorded in the audit log

### Tests

- 15 unit tests in `lib/tests/test_guardrails.py` covering source validation, content tagging, and audit logging
- 3 new integration tests in the enrichment app verifying guardrail rejection, source tagging, and the no-source-data path
- All 213 tests pass

## Guardrail Rules

1. **Source Validation**: PIM (product catalog) is the primary owned source; ACP/DAM content is a valid secondary source only when it contains real data (not a generic placeholder)
2. **Audit Trail**: Every enrichment attempt logs the SKU, source IDs used, and outcome
3. **Empty Source Rejection**: Requests with no internal source data are rejected with `"enrichment not available"`
4. **Content Attribution**: Enriched content is tagged with `_sources` referencing all internal data sources used
