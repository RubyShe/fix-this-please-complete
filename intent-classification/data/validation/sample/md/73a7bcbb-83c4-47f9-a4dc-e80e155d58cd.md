<pr_title>
Add support for static metadata in FSCrawler settings
</pr_title>

<pr_description>
This PR implements static metadata support for FSCrawler, allowing users to define metadata that gets applied to ALL documents without needing individual </pr_description>`.meta.yml` files in each directory.

## Problem

Previously, adding consistent metadata to all documents required placing `.meta.yml` files in every directory being crawled. This was cumbersome for operational metadata like hostname, environment, or data source information that should be the same across all documents from a crawler instance.

## Solution

Added a new `staticTags` field to the `tags` configuration section that allows defining static metadata in the FSCrawler settings file:

```yaml
fs:
  url: "/path/to/docs"
tags:
  staticTags:
    external:
      hostname: "server001"
      environment: "production"
    custom:
      category: "documents"
      source: "filesystem"
```

## Implementation Details

- **Tags Configuration**: Extended `Tags` class with `staticTags` field to hold static metadata
- **Document Processing**: Modified `FsParserAbstract.indexFile()` to apply static metadata after external metadata loading
- **Merging Logic**: Added `DocUtils.getMergedStaticDoc()` method to merge static metadata with documents
- **Priority System**: File-based `.meta.yml` metadata takes precedence over static metadata for conflicts
- **Testing**: Added comprehensive unit tests and integration tests to verify functionality
