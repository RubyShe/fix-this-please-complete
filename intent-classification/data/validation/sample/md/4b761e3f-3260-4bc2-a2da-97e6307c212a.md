Fix timer synchronization: convert ticks to milliseconds in spawn loot time check

## Root Cause

`SpawnerLootGenerator.spawnLootToSpawner()` compared milliseconds against ticks without conversion:

```java
// Before - comparing milliseconds with ticks
long spawnDelay = spawner.getSpawnDelay(); // Returns ticks (e.g., 100)
if (currentTime - lastSpawnTime < spawnDelay) { // Compares ~5000ms with 100 ticks
    return;
}
```

This rendered the early-spawn guard ineffective (5000ms &gt; 100 ticks always passes) and caused timer display drift.

## Changes

- **SpawnerLootGenerator.java:69**: Convert ticks to milliseconds (1 tick = 50ms) to match the existing conversion in `SpawnerGuiViewManager.calculateTimeUntilNextSpawn()`

```java
// After - both operands in milliseconds
long spawnDelay = spawner.getSpawnDelay() * 50L; // Convert ticks to milliseconds
if (currentTime - lastSpawnTime < spawnDelay) {
    return;
}
```

This aligns with the GUI's timer calculation which already performs the same conversion at line 1326.

<pr_title>
Refactor timer synchronization: separate timer management from spawn triggering
</pr_title>

<pr_description>
The spawn timer in `SpawnerRangeChecker` was out of sync with the GUI timer display in `SpawnerGuiViewManager` due to unclear responsibilities and circular dependencies between components.

## Root Cause

The original implementation had two issues:

1. **Unit mismatch**: `SpawnerLootGenerator.spawnLootToSpawner()` compared milliseconds against ticks without conversion
2. **Circular dependencies**: Both `SpawnerRangeChecker` and `SpawnerGuiViewManager` could trigger `activateSpawner()`, creating race conditions and duplicate timer management

## Changes

### Architecture Refactor

Reorganized responsibilities for better synchronization:

- **SpawnerRangeChecker**: Now only manages the active task timer based on player range (doesn't trigger spawns directly)
- **SpawnerGuiViewManager**: Detects timer expiration and triggers loot spawn via `spawnLootToSpawner()`
- **SpawnerLootGenerator**: Spawns loot without time checking (timing controlled externally) and updates `lastSpawnTime`

### Code Changes

1. **SpawnerRangeChecker.java**: Timer task is now a heartbeat that keeps spawner active without triggering spawns
2. **SpawnerGuiViewManager.java**: Changed to call `spawnLootToSpawner()` instead of `activateSpawner()` when timer expires
3. **SpawnerLootGenerator.java**: Removed redundant time check since timing is now managed by GUI

## Benefits

- ✅ Clear separation of concerns
- ✅ Eliminates circular dependencies
- ✅ Single source of spawn triggering (GUI)
- ✅ Better synchronization between timer and spawn logic
- ✅ Easier to maintain and debug




</pr_description>
