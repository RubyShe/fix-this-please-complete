> `;
&gt; ```
&gt; 
&gt; 
&gt; In v6, because of the syntax error on the line-height line, background-color: green; is also ignored.

## Summary

I've completed the work on fixing CSS syntax error handling in styled-components v6. Here's what was done:

### Issues Fixed
1. **Original Issue**: Unbalanced closing braces (e.g., `line-height: ${() => "14px}"}`) no longer cause all subsequent styles to be ignored
2. **Issue #5613**: JS-style line comments (`//`) in multiline declarations like `calc()` no longer cause parsing errors

### Implementation
Added three new functions to `utils/stylis.ts`:
- `stripLineComments()`: Strips `//` comments anywhere in CSS while preserving strings (e.g., `content: "http://..."`)
- `hasUnbalancedBraces()`: Fast O(n) check to detect CSS with brace issues
- `sanitizeCSS()`: Removes only problematic declarations while preserving valid subsequent styles

### Performance Considerations
- **Fast path**: Valid CSS passes through unchanged with minimal overhead (single O(n) scan)
- **Slow path**: Only triggered when issues are detected, removes only affected declarations
- Addressed code review feedback for performance (caching `css.length`, consistent bounds checking)

- Unbalanced closing braces in various positions
- Multiple malformed declarations
- Braces inside quoted strings (preserved correctly)
- Line comments at start of line, end of line, and inside multiline declarations
- URLs in strings preserved (e.g., `http://`)
