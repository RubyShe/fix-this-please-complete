<issue_title>Incidents do not get handled correctly on job worker to Camunda user task migration</issue_title>
<issue_description>### Description

When migrating a job-worker user task to a Camunda user task, an incident that occurred in the job worker is migrated to the new element instance and not cleaned up when the job is cancelled. This leads to the incident still being present in the zeebe state for the job, as well as on the element instance to incident mapping.

Needs to be backported to 8.8.

### Steps to reproduce

1. Deploy a process with job-worker user task and wait for the job to be created (this means we can't use incidents created by invalid forms, because in that case the job does not get created)
2. Fail the job-worker job
3. Migrate the user task (that now has an incident) to a Camunda user task


### Current behavior

The migrated user task has an incident related to the job failure. Retries to resolve the incident fail since the job is not active anymore (it has been cancelled)

### Expected behavior

There are no incidents related to the cancelled job worker on the migrated task (neither in the zeebe state, nor in secondary storage).

### Workaround

No known workaround.


### Environment

SaaS &amp; SM

### Version

- Component Version: 8.8.19, 8.9.0-rc1


### Rootcause

During the migration the job for the job worker gets canceled but this does not remove any incidents related to the job from the state. Instead the incident is also migrated to the new user task

### Solution ideas

1. Resolve any incidents on the job during the migration.
2. Prevent the incident from being migrated for this type of migration -&gt; ensure the elementInstance does not contain a link to it anymore (check if it will still get cleaned up eventually)
