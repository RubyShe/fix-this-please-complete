<pr_title>
Remove discriminator metadata when subtypes lack usage
</pr_title>

<pr_description>
When a discriminated base model has subtypes where only some are used in operations, the unused subtypes get filtered from `sdkPackage.models` but remain referenced in the base model's `discriminatedSubtypes` map. This creates invalid references to types unavailable to language emitters.

```typespec
@discriminator("kind")
model Pet { kind: string; }
model Cat extends Pet { kind: "cat"; }
model Dog extends Pet { kind: "dog"; }

op read(): { @body body: Cat };  // Only Cat used, Dog has no usage
```

Before: `Pet.discriminatedSubtypes = { cat: Cat, dog: Dog }` but `Dog` not in models list  
After: `Pet.discriminatedSubtypes = undefined`

## Changes

- **Added `cleanupDiscriminatorForUnusedBase()`** in `types.ts` after usage propagation
  - Detects base models with unused subtypes (no Input/Output usage)
  - Clears `discriminatedSubtypes` and `discriminatorProperty` from base
  - Clears `discriminatorValue` from all subtypes in hierarchy
  - Includes circular reference protection in hierarchy traversal

- **Added helper `hasInputOrOutputUsage()`** for consistent usage flag checking

- **Test coverage** for Pet/Cat/Dog scenario validates discriminator removal

Language emitters now see clean model hierarchies without references to unavailable types.
