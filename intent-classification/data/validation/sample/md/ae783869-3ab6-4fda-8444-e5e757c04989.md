<pr_title>
Add JavaScript error capture and auto-healing for MCP dashboard
</pr_title>

<pr_description>
JavaScript errors in the MCP dashboard were not being captured or reported, leaving silent failures untracked. This implements end-to-end error capture, GitHub issue creation with full context, and auto-healing workflow integration.

## Architecture

```
Browser → error_capture.js → /api/report-js-error → js_error_reporter.py 
    → GitHub Issue (labels: bug, javascript, dashboard, auto-healing)
    → auto_healing_coordinator → GitHub Actions → Draft PR
```

## Implementation

### Frontend (`error_capture.js`)
- Captures unhandled errors and promise rejections via global event listeners
- Intercepts console methods to maintain history (last 100 entries)
- Tracks user actions: clicks, form submissions, navigation (last 50 events)
- Debounces reporting (1s) to prevent flooding

### Backend (`js_error_reporter.py`)
- Formats error reports with stack traces, console history, action timeline
- Creates detailed GitHub issues via CLI with structured context
- Triggers `auto_healing_coordinator` with javascript_error pattern
- Maintains error history and statistics

### API (`dashboard_error_api.py`)
- `POST /api/report-js-error` - Receives error payloads
- `GET /api/js-error-stats` - Returns error type distribution
- `GET /api/js-error-history?limit=N` - Returns recent reports

### Integration
- Registered routes in `admin_dashboard.py`
- Added script include in `mcp_dashboard.html`
- Leverages existing GitHub Actions auto-healing workflows

## Error Report Example

```json
{
  "errors": [{
    "type": "error",
    "message": "Cannot read property 'data' of undefined",
    "stack": "TypeError: Cannot read property...\n  at loadDashboard (app.js:42:15)",
    "consoleHistory": [
      {"level": "warn", "message": "API slow response", "timestamp": "..."}
    ],
    "actionHistory": [
      {"type": "click", "element": "BUTTON", "id": "refresh-btn"}
    ]
  }]
}
```

GitHub issues are created with labels `bug`, `javascript`, `dashboard`, `auto-healing` to trigger the existing `issue-to-draft-pr.yml` workflow.

- **Tests:** 8 unit tests covering error formatting, API endpoints, statistics
