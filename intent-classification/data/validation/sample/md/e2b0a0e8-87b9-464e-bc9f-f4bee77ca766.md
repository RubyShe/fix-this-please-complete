### Problem Identified
The test `deep-links to PDF modal with doc_id and chunk_id in URL` in `ui/frontend/src/tests/app.test.tsx` was timing out after 5 seconds, causing the CI to fail.

### Root Cause
The test was experiencing two main issues:
1. **React Testing Library act() warnings**: Async state updates in the React components weren't properly wrapped in `act()`, causing the test framework to lose track of pending async operations
2. **Insufficient timeouts**: The test was waiting only 5 seconds for the search to be called, but in the test environment with multiple async operations (config loading, model combo loading, facets loading, search), this wasn't enough time

### Solution Implemented
**Commit cfb3f04**: Fixed the test by:
1. Imported `act` from `@testing-library/react`
2. Wrapped the `render()` call in `act()` to properly handle initial rendering
3. Wrapped all `waitFor()` calls in `act()` to properly handle async state updates
4. Increased the search wait timeout from 5s to 10s
5. Increased the PDF viewer appearance timeout from 3s to 5s
6. Added an overall test timeout of 30 seconds (using Jest's third parameter)
7. Wrapped the overlay click in `act()` for proper state update handling

**Commit ad293a0**: Restored the correct package-lock.json file which had been corrupted by running `npm install` locally with npm v11 instead of the CI's npm v10.8.2.

### Verification
- ✅ CI runs 22026515043 and 22026519529 completed with no failed jobs
- ✅ All tests now pass
- ✅ Package-lock.json remains in correct state (with yaml@2.8.2 dependency)

The fix ensures that React Testing Library properly tracks all async state updates, preventing race conditions and timeout issues in the deep-link test.
