Location: Inside the _to_seconds function (the re.finditer call).

Problem: The group (?P     \d+(?:\.\d+)?)\s* combined with the long list of optional units can be exploited if a user provides a very long string of numbers and spaces without a valid unit terminator.

Fix Required: Simplify the numeric matching and ensure the unit boundaries are strict.

Issue 2: "From...To..." Extraction
File: backend/main.py

Location: m = re.search(r"from\s+([^\s]+(?:\s*[a-z]+)?)\s+to\s+([^\s]+(?:\s*[a-z]+)?)", text)

Problem: The nested optional groups ([^\s]+(?:\s*[a-z]+)?) are the culprit. When the engine fails to find a match, it tries every possible permutation of spaces and letters, leading to exponential complexity (specifically triggered by strings like "from !" followed by many "aa").

Fix Required: Refactor to avoid nested quantifiers. Use a simpler non-whitespace match or a non-backtracking approach.

Issue 3: "Long" Duration Parsing
File: backend/main.py

Location: m4 = re.search(r"(?:to\s+)?([^\s]+(?:\s*[a-z]+)?)\s+long", text)

Problem: Similar to Issue 2, the ([^\s]+(?:\s*[a-z]+)?) pattern is unstable. CodeQL notes it fails on strings with many repetitions of !.

Fix Required: Replace the capture group with a more restrictive pattern that doesn't "loop inside a loop."

Issue 4: "Set to/Make it" Parsing
