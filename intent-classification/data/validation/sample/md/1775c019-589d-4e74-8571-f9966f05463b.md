## Verification safeguard: `--verify` mode

The script includes a `--verify` flag that cross-checks its heuristic classification against Maven's actual plugin resolution. This is the **authoritative source of truth** and should be run periodically to catch classification drift.

### How `--verify` works

1. **Discover all Maven modules**: parse `pom.xml` `<modules>` recursively
2. **For each module with test sources**: run `mvn -pl <module> surefire:test failsafe:integration-test -X -DskipTests` and parse debug output for `[DEBUG] Selecting test class: <fqcn>` lines
3. **Compare**: surefire-selected → expect `unit`, failsafe-selected → expect `integration`/`acceptance`/etc.
4. **Report mismatches**: output a diff showing disagreements between heuristic and Maven

Make sure this doesn't actually run the tests as it would take to long, it should just trigger a dry run to explore all tests that WOULD run.

### When to run
- After adding new modules or restructuring `qa/` directories
- After adding new tests to ensure they will be captured in CI jobs
- After changing surefire/failsafe plugin config in any `pom.xml`
- As a periodic CI check (optional — can be expensive for full monorepo)

### Limitations
- Slow (runs Maven per module) — not for every invocation
- Profile-specific test configurations may not be captured in default run
