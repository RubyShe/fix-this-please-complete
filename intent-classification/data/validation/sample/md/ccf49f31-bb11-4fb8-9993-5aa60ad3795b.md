## Summary

I analyzed the remaining Windows test failure reported by @kzu. The error:

```
Microsoft.Build.Exceptions.InvalidProjectFileException : The SDK resolver assembly "C:\Program Files\Microsoft Visual Studio\2022\Enterprise\MSBuild\Current\Bin\SdkResolvers\Microsoft.DotNet.MSBuildSdkResolver\Microsoft.DotNet.MSBuildSdkResolver.dll" could not be loaded.
```

This is a **pre-existing issue** with the Windows test infrastructure, not caused by my cross-platform changes. It happens because:

1. Windows builds use Desktop MSBuild (`msbuild -r`)
2. `ThisAssembly.Project.MSBuildBinPath` captures the VS MSBuild path at build time
3. When inline project tests try to build SDK-style projects, VS MSBuild's SDK resolver conflicts with the .NET SDK

The original workflow (before my changes) only ran on `windows-latest` and had the same underlying issue. My changes successfully enabled Linux testing:
- **Linux**: 243 passed, 66 skipped ✅
- **Windows**: Has pre-existing SDK resolver conflicts

I replied to the comment asking @kzu whether to investigate a fix for the Windows SDK resolver issue or if it's a known/acceptable limitation.
