<pr_title>
feat: streaming multipart uploads via Mongoose v7 MG_EV_HTTP_HDRS escape hatch
</pr_title>

<pr_description>
`MG_EV_HTTP_MSG` fires only after Mongoose v7 fully buffers the entire request body, making OTA uploads of 1–2 MB firmware impossible on ESP32 targets with ~300 KB free heap.

## Approach

Mongoose v7's `http_cb` contains a built-in escape hatch: after firing `MG_EV_HTTP_HDRS`, it checks `if (c->recv.len != old_len)` — if changed, it sets `c->pfn = NULL` and returns, handing all subsequent `MG_EV_READ` events directly to the user handler. Calling `mg_iobuf_del(&nc->recv, 0, head_len)` during HDRS handling exploits this, enabling true incremental chunk delivery.

## Changes

- **`src/MongooseHttpServerRequestUpload.h/.cpp`**
  - Constructor detects `multipart/form-data`, calls `mg_iobuf_del` to strip headers and trigger http_cb detach, nulls `_msg->body` (prevents stale-pointer dereference in `mg_http_get_var`), then invokes `handleRequest` once for auth/init
  - `onReceive()` override drives `processBodyData()` on each `MG_EV_READ`
  - `processBodyData()` is a state machine: `PREAMBLE → PART_HEADERS → PART_BODY → COMPLETE`, dispatching `MG_EV_HTTP_PART_BEGIN/DATA/END` callbacks incrementally with a holdback of `boundary.size()-1` bytes to prevent partial-boundary splits
  - Non-multipart requests fall through unchanged to the original `handleMessage()` path

- **`tests/unit/test/test_http_server.cpp`**
  - 4 new unit tests: single-part, multi-part, zero-byte, and chunked delivery (split across multiple `onReceive` calls)

## Usage pattern

The correct upload endpoint pattern is unchanged — `onRequest` handles auth/state init only; the response must be sent from `onUpload` at `MG_EV_HTTP_PART_END`:

```cpp
server.on("/update", HTTP_POST,
  [](MongooseHttpServerRequest *req) {
    // auth check only — do NOT send response here
  },
  [](MongooseHttpServerRequest *req, int ev,
     const String &name, const String &filename,
     const uint8_t *data, size_t len) -> size_t {
    if (ev == MG_EV_HTTP_PART_DATA) {
      Update.write((uint8_t*)data, len);
    } else if (ev == MG_EV_HTTP_PART_END) {
      req->send(Update.end(true) ? 200 : 500);
    }
    return len;
  }
);
```

Peak heap usage is now bounded by chunk size rather than firmware binary size.
</pr_description>
