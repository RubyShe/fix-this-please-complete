Three independent bugs in shared packages: Prometheus label-value series leaked on mutex close, a `statusCode == 0` guard that could never fire, and a listener panic that took down the entire `Emit` call.

## `pkgs/lockmetrics` — metric leak + per-call label hash overhead
- `Close()` now calls `DeletePartialMatch({"lock": name})` on all four metric vecs, removing every label-value series tied to the closed mutex. Previously only the `liveCollector` map entry was removed, silently leaking series for every dynamic resource (bucket, table, etc.).
- Pre-curry `activeReaders` gauge to lock name at `New()` time (`activeReadersLock prometheus.Gauge`); `RLock`/`RUnlock` now call `Inc()/Dec()` directly instead of re-hashing labels on every acquisition.

## `pkgs/handler` — dead branch in `Write()`
`NewResponseWriter` initialized `statusCode` to `200`, making the `if statusCode == 0` guard in `Write()` unreachable. `statusCode` is now zero-initialized; `Write()` sets it to `200` on first call, `StatusCode()` returns `0` when neither `WriteHeader` nor `Write` has been called.

## `pkgs/events` — listener panic crashes `Emit`, O(n) unsubscribe
- Added `ErrListenerPanicked` sentinel and a `safeCall` helper that wraps each listener in `recover()`; panics surface as `fmt.Errorf("%w: %v", ErrListenerPanicked, r)` instead of unwinding the caller.
- `removeByID` replaced `append([:i], [i+1:]...)` (O(n) shift + allocation) with swap-with-last (O(1), no allocation), zeroing the vacated tail slot for GC.
